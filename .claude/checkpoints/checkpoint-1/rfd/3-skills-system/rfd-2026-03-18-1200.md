# RFD-3: Skills System + Registry

**Status:** Complete
**Date:** 2026-03-18
**Depends on:** RFD-1 (Core AgenticReviewer)

## Goal

Implement the skills system: discovery, lazy loading, tool registration on Pydantic AI agents, and the first builtin skill (`searching-content`). Follows the Anthropic Agent Skills spec with 3-level progressive disclosure.

## Architecture

### 3-Level Progressive Disclosure
- **L1 (discover)**: Parse SKILL.md frontmatter → `{name, description}` (~100 tokens/skill)
- **L2 (enable)**: Import `tools.py` → load `FunctionToolset` for selected skills
- **L3 (on-demand)**: `get_skill_details` meta-tool returns full SKILL.md body at agent's request

### Skill Folder Structure (Anthropic Agent Skills spec)
```
skills/builtin/searching-content/
├── SKILL.md     # YAML frontmatter (name, description) + markdown body
└── tools.py     # Module-level `toolset` variable (FunctionToolset)
```

### Naming Rules (Anthropic spec)
- Max 64 chars, lowercase letters/numbers/hyphens only
- No reserved words ("anthropic", "claude")
- Description in third person, max 1024 chars

## Design Decisions

- **Separate `_meta_tool.py` module**: The `get_skill_details` meta-tool needs real type objects at runtime (Pydantic AI resolves `RunContext[ReviewDeps]` via `get_type_hints`). `from __future__ import annotations` makes these string-only, breaking tool registration. Solution: keep the meta-tool in its own module without future annotations.
- **Auto-discovery on enable**: If `enable()` is called without prior `discover()`, it auto-discovers. Reduces boilerplate.
- **Builtin-first deduplication**: If a custom skill has the same name as a builtin, the builtin wins and the custom is skipped with a warning.
- **Integration with AgenticReviewer**: `_setup_skills()` method handles registry lifecycle. Skills are only set up in agentic mode with `self.skills` configured. Toolsets are passed through to `_build_agent()`.
