# RFD-5: Flagging + Revisit System

**Date:** 2026-03-18
**Status:** COMPLETE

## Goal

Implement a flagging system that allows agents to flag items for revisiting when they cannot be confidently assessed. After all items in a round are processed, flagged items are re-reviewed with updated memory context. Unresolved flags are surfaced in the DataFrame.

## Architecture

### FlagStore (`flags/store.py`)
- Single `flags.json` file with `[{item_id, reason, resolved}]` entries
- `asyncio.Lock` on all write operations for concurrent safety
- Atomic writes: write-to-temp-then-rename pattern
- Methods: `add_flag()`, `resolve_flag()`, `get_unresolved()`, `get_flag()`, `list_flags()`, `count()`
- Update-in-place: re-flagging an already-flagged item updates the reason
- Re-flagging after resolve creates a new entry (resolved + new unresolved coexist)

### Skill (`flagging-items/`)
- 3 tools: `flag_for_revisit(reason)`, `list_flagged_items()`, `resolve_current_flag()`
- Follows Anthropic Agent Skills spec (SKILL.md with YAML frontmatter)
- Uses `ModelRetry` for graceful error handling when store unavailable

### Workflow Integration
- `AgenticWorkflow` creates shared FlagStore per reviewer/round when `working_dir` is set
- After processing all items, calls `_revisit_flagged_items()` if `revisit_flagged=True`
- Revisit pass: re-reviews flagged items sequentially (not concurrently) to leverage updated memories
- Revisit text includes original flag reason for context
- After revisit, still-unresolved items get `round-{ID}_{NAME}_flagged` (bool) and `round-{ID}_{NAME}_flag_reason` (str) columns

### System Prompt Integration
- Flag summaries (item_id + reason) injected as "# Flagged Items" section
- Only in agentic mode (max_iterations > 1)
- Helps agent recognize previously-flagged items during revisit

### Storage Layout
```
working_dir/round_{ID}/agent_{NAME}/flags/flags.json
```

## Deviations from Plan

- Plan mentioned `_flagged` and `_flag_reason` as column names; implemented as `round-{ID}_{NAME}_flagged` and `round-{ID}_{NAME}_flag_reason` to follow existing column naming convention and support multiple reviewers.
- Plan mentioned `escalation to user`; implemented by surfacing unresolved flags as DataFrame columns which the user can inspect.
